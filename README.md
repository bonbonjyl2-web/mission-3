## Make와 Zapier 비교 분석 보고서

---

## 1. 개요
Make와 Zapier는 모두 **노코드 자동화 도구**로, Google Forms 응답 수집, Google Sheets 기록, Gmail 자동 발송 등의 업무를 자동화할 수 있다.  
다만 두 도구는 **실행 방식, 조건 분기 구조, 과금 단위, 오류 처리, 로그 확인 방식**에서 차이를 보인다.

---

## 2. 주요 비교 항목

### 2-1. 단계별 기능 비교

| 비교 항목 | Make (구 Integromat) | Zapier | 분석 |
|---|---|---|---|
| **트리거 방식** | Google Forms 또는 Google Sheets의 새 행 감지를 통해 실행 가능. 웹훅 기반 또는 실시간에 가까운 감지가 가능함 | Google Forms 트리거는 일반적으로 폴링(Polling) 방식이라 무료/하위 플랜에서는 1~15분 정도 지연될 수 있음 | **즉시 응답이 중요한 경우 Make가 유리** |
| **조건 분기(오전/오후 등)** | Router 모듈로 하나의 시나리오 안에서 여러 경로를 분기하고, 각 경로에 Filter 조건 적용 가능 | Paths 기능으로 분기 가능하지만 보통 상위 유료 플랜에서 지원. 무료/하위 플랜은 Zap을 여러 개로 나눠야 함 | **복잡한 분기 로직은 Make가 더 효율적** |
| **시트 기록** | Google Sheets “Add a Row” 모듈 사용. 필드 매핑 자유도가 높고 함수/포맷 활용이 편리함 | Google Sheets “Create Spreadsheet Row” 액션 사용. 기본 매핑은 쉽지만 가공 작업은 추가 단계가 필요함 | **단순 입력은 둘 다 가능, 가공 포함 시 Make가 유리** |
| **본문 개인화** | if, formatDate, replace 등 내장 함수를 시나리오 안에서 바로 사용 가능 | Formatter by Zapier를 별도 단계로 추가해야 하는 경우가 많음 | **텍스트 가공이 많을수록 Make가 효율적** |
| **Gmail 발송** | Gmail “Send an Email” 모듈 지원, HTML 템플릿·첨부파일 가능 | Gmail “Send Email” 액션 지원, 사용법은 단순하고 직관적 | **기능은 유사하나 사용 편의성은 Zapier가 쉬움** |
| **에러 처리** | Error Handler 라우트를 시나리오 내부에 구성 가능. 재시도, 우회 경로, 대체 처리 가능 | 기본 자동 재시도는 제공하지만 세부 분기형 오류 처리는 제한적 | **안정성과 예외 처리 측면에서 Make가 강함** |
| **실행 단위 계산** | 시나리오 실행 시 사용된 모듈 수만큼 Operation 소모 | 트리거와 액션이 각각 Task로 계산됨. 멀티스텝일수록 소모량 증가 | **같은 자동화라도 Zapier가 더 빨리 소모될 수 있음** |
| **실행 로그 확인 방식** | 시나리오 실행 내역에서 각 모듈별 입력값·출력값·오류 위치를 시각적으로 확인 가능 | Task History에서 단계별 성공/실패 여부와 데이터 흐름 확인 가능 | **Make는 시각적 분석에 강하고, Zapier는 단순 확인에 편리** |

## 3. 실행 로그 확인 방식 비교

실행 로그는 자동화가 제대로 작동했는지, 오류가 어디서 발생했는지 확인하는 데 매우 중요하다.

### 3-1. Make의 실행 로그 확인 방식
- 시나리오 실행 후 **각 모듈이 연결된 흐름도 형태로 기록**
- 모듈별로 **입력 데이터, 출력 데이터, 오류 메시지**를 확인 가능
- 어느 단계에서 실패했는지 **시각적으로 바로 파악 가능**
- 필터 조건이 왜 통과/실패했는지도 추적 가능

**장점**
- 복잡한 분기 구조를 분석하기 쉽다.
- 디버깅에 강하다.
- 여러 경로가 있는 자동화에 적합하다.

**단점**
- 처음 보는 사용자에게는 인터페이스가 다소 복잡할 수 있다.

### 3-2. Zapier의 실행 로그 확인 방식
- **Task History**에서 각 Zap 실행 기록을 확인
- 단계별 성공/실패 여부와 전송된 데이터를 볼 수 있음
- 어떤 스텝에서 오류가 났는지 비교적 쉽게 확인 가능

**장점**
- 구조가 단순해서 초보자가 보기 쉽다.
- 특정 작업이 성공했는지만 빠르게 점검하기 좋다.

**단점**
- 다중 분기나 복잡한 예외 처리 흐름을 한눈에 보기는 어렵다.
- 세밀한 분석은 Make보다 제한적이다.

## 4. UI/UX 및 설정 난이도 비교

| 항목 | Make | Zapier |
|---|---|---|
| UI/UX | 시각적 플로우 기반. 흐름 전체를 한눈에 볼 수 있음 | 단계별 마법사 형태. 설정 과정이 단순함 |
| 초기 학습 난이도 | 다소 있음 | 낮음 |
| 초보자 친화성 | 상대적으로 낮음 | 높음 |

### 해석
- Zapier는 진입장벽이 낮아 비개발자에게 적합하다.
- Make는 익숙해지면 더 복잡한 자동화를 효율적으로 설계 가능하다.

---

## 5. 무료 플랜 및 비용 효율 비교

| 항목 | Make | Zapier |
|---|---|---|
| 무료 플랜 활용도 | 비교적 넉넉한 편. 소규모 자동화 운영에 유리 | 무료 플랜은 스텝 수, 분기 기능, 실행 주기 측면에서 제약이 큼 |
| **비용 구조** | Operation 기반 | Task 기반 |
| **복잡한 시나리오 비용 효율** | 상대적으로 유리 | 스텝이 많아질수록 불리할 수 있음 |

### 해석
- **월 수십~수백 건 정도의 자동화**에서는 Make가 더 경제적일 가능성이 높다.
- Zapier는 사용이 쉽지만, **여러 단계가 추가될수록 Task 소모가 빠르게 증가**한다.

## 6. 연동 확장성과 유지보수성 비교

| 항목 | Make | Zapier |
|---|---|---|
| **워크플로우 확장성** | Router와 함수, 모듈 조합으로 유연한 확장 가능 | 간단한 연결에는 좋지만 복잡한 분기 구조는 유료 기능 의존도가 큼 |
| **유지보수 편의성** | 한 시나리오 안에서 분기 관리 가능 | 무료/하위 플랜에서는 여러 Zap으로 분산될 수 있어 관리 포인트 증가 |
| **다른 앱 연동 시 비용 효율** | 스텝이 늘어나도 상대적으로 유리한 편 | 앱 추가 및 단계 증가 시 Task 소모가 빠름 |

### 해석
향후 설문 문항 추가, 오전/오후 외 다른 분류, 알림 앱 연동 등으로 확장할 가능성이 있다면 **Make가 구조적으로 더 유리하다.

## 7. 도구별 장단점 정리

### 7-1. Make의 장점
1. **실시간에 가까운 트리거 처리**가 가능하다.
2. **Router와 Filter**를 이용해 복잡한 분기 로직을 한 시나리오에서 관리할 수 있다.
3. 내장 함수가 강력하여 **본문 가공과 데이터 변환이 편리**하다.
4. **에러 처리와 로그 분석 기능이 강력**하다.
5. 동일 예산에서 **더 많은 자동화 작업을 처리할 가능성**이 높다.

### 7-2. Make의 단점
1. 처음 사용할 때 **학습 부담이 있다**.
2. 인터페이스가 초보자에게는 다소 복잡해 보일 수 있다.
3. 단순 자동화만 필요한 경우에는 설정이 과하게 느껴질 수 있다.

### 7-3. Zapier의 장점
1. **설정 과정이 쉽고 직관적**이다.
2. 단계별 마법사 방식이라 **초보자도 빠르게 시작 가능**하다.
3. Gmail, Google Sheets 등 기본 자동화는 손쉽게 연결할 수 있다.
4. 간단한 워크플로우에서는 빠른 구축이 가능하다.

### 7-4. Zapier의 단점
1. 무료/하위 플랜에서는 **분기 처리 기능이 제한적**이다.
2. 폴링 방식으로 인해 **실행 지연이 발생할 수 있다**.
3. Formatter 등 **추가 스텝이 자주 필요**해 Task 소모가 늘어난다.
4. 복잡한 자동화에서는 **여러 Zap으로 나뉘어 관리가 번거로울 수 있다**.
5. 세부적인 오류 분기나 예외 처리에는 한계가 있다.

---

## 8. 종합 결론

---

### Make가 더 적합한 경우
- 신청 직후 **즉시 자동 응답**이 필요할 때
- 오전/오후처럼 **조건 분기 로직이 필요한 경우**
- 하나의 워크플로우에서 **여러 경로를 통합 관리**하고 싶을 때
- 향후 문항 추가, 다른 앱 연결 등 **확장 가능성**이 클 때
- **비용 효율**을 중요하게 볼 때

### Zapier가 더 적합한 경우
- 자동화 경험이 거의 없는 사용자가 **빠르게 구축**하고 싶을 때
- 분기 없이 **단순한 1:1 연결 작업**이 주된 목적일 때
- 세밀한 제어보다 **쉬운 사용성**을 우선할 때

---

## 9. 보고서용 한줄 요약
> **Make는 실시간 처리, 조건 분기, 오류 대응, 비용 효율 면에서 강점을 가지며, Zapier는 직관적인 UI와 쉬운 설정이 장점인 자동화 도구이다. 복잡한 업무 자동화와 확장성을 고려하면 Make가, 빠른 입문과 단순 자동화에는 Zapier가 더 적합하다.**

---

## 10. 선택 도구 선정
Make 를 선택한다. Make는 실시간에 가까운 트리거 처리가 가능하며 Router와 Filter를 이용해 복잡한 분기 로직을 한 시나리오에서 관리할 수 있다. 작업 시 두 모듈 사이의 연결선(점선) 가운데 플러스 버튼을 눌러 Router를 추가하여 각 채널로 보내는 조건부 분기를 Zapier보다 훨씬 직관적으로 만들 수 있어서 초보자의 경우 쉽게 이해하고 진행할 수 있다.

## 2. 자동화할 반복 업무 정의

### 🔴 문제 상황
뷰티 업계 마케터는 매일 아래 업무를 수동으로 반복 수행하고 있었습니다.

```
[기존 수동 프로세스]

① 포털/뉴스 사이트 접속
        ↓
② 키워드 검색 (뷰티, 성분, 트렌드 등)
        ↓
③ 기사 하나씩 읽고 중요도 판단
        ↓
④ 엑셀에 제목/링크/분류 수동 입력
        ↓
⑤ 팀 채널(카카오톡/이메일)에 복붙 공유
        ↓
⑥ 소요 시간: 매일 1~2시간
```

### 📌 정의된 반복 업무
> **"뷰티 산업 관련 뉴스를 매일 수집하여 카테고리별로 분류하고, 담당 채널에 공유하는 업무"**

| 구분 | 내용 |
|------|------|
| **업무명** | 일일 뷰티 뉴스 수집·분류·공유 |
| **반복 주기** | 매일 (뉴스 발행 시마다) |
| **소요 시간** | 약 1~2시간/일 |
| **문제점** | 휴먼 에러, 누락, 분류 기준 불일치, 퇴근 후 대응 불가 |

## 4. 워크플로우 설계

### 4-1. 전체 흐름 다이어그램

```
┌─────────────────────────────────────────────────────────────┐
│                    자동화 워크플로우 전체 구조                    │
└─────────────────────────────────────────────────────────────┘

[TRIGGER]
  📡 RSS Feed
  └─ 새 기사 감지 시 자동 실행
          │
          ▼
[ACTION 1]
  🤖 OpenAI (ChatGPT)
  └─ 기사 제목 + 내용 → AI 분류
  └─ 출력값: "연구개발" / "뷰티" / "기타"
          │
          ▼
[ACTION 2]
  📊 Google Sheets
  └─ 날짜 / 제목 / 분류 / URL 자동 저장
          │
          ▼

          │

키워드
    │     │              │
    ▼     ▼              ▼

```

### 4-2. 모듈별 상세 설명

#### 🟠 Trigger: RSS (모듈 #2)
```
- 역할: 뷰티 뉴스 RSS 피드 실시간 감지
- 동작: 새 기사 등록 감지 시 워크플로우 자동 시작
- 출력값: 기사 제목(Title), 본문(Description), URL, 발행일
```

#### 🟢 Action 1: OpenAI ChatGPT (모듈 #13)
```
[프롬프트 설계]

아래 기사 내용을 분석하여 가장 적합한 단어 하나로만 분류해줘.
선택 가능한 단어: [연구개발, 뷰티, 기타]

- 연구개발: 성분, 임상, 특허, 기술, 신소재, 학술, 규제, 수출 관련 기사
- 뷰티: 신제품, 메이크업, 트렌드, 이벤트, 브랜드, 마케팅 관련 기사
- 기타: 위 두 범주에 해당하지 않는 기사

기사 제목: {{2. Title}}
기사 내용: {{2. RSS fields: description}}

```

#### 🟢 Action 2: Google Sheets (모듈 #3)
```
- 역할: 분류된 뉴스 데이터 자동 저장
- 저장 컬럼 구성:

  A열: 수집 날짜/시간
  B열: 기사 제목
  C열: ChatGPT 분류 결과
  D열: 기사 원문 URL
  E열: RSS 피드 출처
```

#### 🔀 Router (모듈 #9): 조건 분기
```
1st 경로 - "중요/상시간 키워드"
  └─ 조건: 분류값 = "연구개발"
  └─ 실행: Discord 채널 메시지 전송
  └─ 실행 횟수: 0회 (캡처 기준)

2nd 경로 - "대중성 키워드"
  └─ 조건: 분류값 = "뷰티"
  └─ 실행: Telegram Bot 메시지 전송
  └─ 실행 횟수: 4회 ✅

Fallback - "기타/Fallback"
  └─ 조건: 위 조건 모두 미해당
  └─ 실행: Gmail 이메일 발송
  └─ 실행 횟수: 1회 ✅
```
